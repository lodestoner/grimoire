# House code style

- Match the conventions of the surrounding code first (naming, indentation, quoting, comment density). Local consistency beats any general rule below.
- Clear over clever. No needless dependencies. Idiomatic for the language at hand.
- Comments explain the non-obvious "why", never restate the "what". Keep them sparse.
- Preserve existing behavior unless a change is explicitly requested.
- Use descriptive names; avoid 1-letter vars except loop indices.
- Output only the code — no markdown fences, no commentary, no preamble.
